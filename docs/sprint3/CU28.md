## API autenticada

Todas las rutas comienzan con `/api/`. Las APIs de cupones de tienda requieren su propietario con rol empresa; las de cliente requieren rol cliente.

| Método/ruta | Función |
| --- | --- |
| GET/POST `tiendas/{tienda}/cupones/` | Listar/crear cupones y segmentos de esa tienda |
| PATCH `tiendas/{tienda}/cupones/{id}/` | Editar/activar/desactivar, con validación de propietario |
| GET `marketing/cupones/` | Ofertas vigentes para el cliente autenticado |
| POST `marketing/cupones/validar/` | `{tienda_id,codigo}`; cotiza sobre el carrito real |
| GET `marketing/notificaciones/?antes={id}` | Bandeja propia; 50 registros/página, `siguiente` y `no_leidas` |
| PATCH `marketing/notificaciones/{id}/` | Marcar un aviso propio como leído |
| POST `usuarios/dispositivos/` | `{token,plataforma:android/ios,activo:true/false}`; nunca retorna el token |

Checkout y PaymentIntent aceptan `cupones: {"id_tienda":"CODIGO"}`. El servidor recalcula precios, fechas, segmento, mínimo y límites por cliente/globales, bloquea los usos concurrentes y registra descuento/Pago sobre el total real. Cotizar no consume usos.

## CU-28 y procesos automáticos

Ejecutar esta tarea periódicamente en la infraestructura del backend (por ejemplo cada hora). La programación debe habilitarla el equipo cuando despliegue la rama; este cambio no instala un cron ni envía mensajes reales durante las pruebas.

```powershell
python server/manage.py procesar_marketing --dry-run
python server/manage.py procesar_marketing
```

Incluye cuatro comandos que también se pueden ejecutar por separado: `notificar_carritos_push`, `procesar_carritos_abandonados`, `procesar_promociones`, `procesar_recordatorios_recompra`.

Recompra: solo pedidos entregados; umbral inicial 15 días, máximo 60 y pausa de 7 días por cliente/tienda. Si hay historial, estima el intervalo mediano entre compras entregadas, dentro de esos límites. Un pedido posterior no cancelado suprime el recordatorio anterior. No ofrece productos inactivos/sin stock. No crea pedidos, pagos ni descuentos ficticios. Configuración: `RECOMPRA_DIAS`, `RECOMPRA_MAX_DIAS`, `RECOMPRA_COOLDOWN_DIAS`.

Carritos: respeta horas de inactividad y campañas activas. Un evento por ciclo de actividad; registra conversión al completar checkout. Los avisos de bandeja no se cuentan como correos enviados (`correo_enviado`). Promociones: solo clientes vinculados a la tienda y al segmento; publica también cupones cuya vigencia comienza en una fecha posterior. La clave única por evento evita duplicar avisos al repetir las tareas.

## Firebase: configuración del equipo

Actualización 26/10/2026: Firebase está configurado localmente y se verificó un envío real al Pixel 8; consultar `docs/INTEGRACION-FIREBASE.md`. La bandeja persiste aunque no exista Firebase. `FCM_ENABLED` es falso por defecto; `solo_bandeja` no significa push entregado. El SDK envía después del commit, desactiva tokens no registrados y registra fallos sin imprimir tokens/credenciales.

Para preparar otro entorno, usar el proyecto Firebase del equipo y su registro Android `bo.kantu.kantu_market`. En el servidor proporcionar credenciales mediante Application Default Credentials o `FIREBASE_CREDENTIALS_FILE` apuntando a un archivo privado, y habilitar `FCM_ENABLED=True`. Nunca copiar la cuenta de servicio al móvil ni a Git. Documentación oficial: https://firebase.google.com/docs/admin/setup

En otro equipo, usar `scripts/configurar_firebase.py` de la app con el `google-services.json` del mismo proyecto. En esta computadora ya se reconstruyó e instaló el APK configurado y Google aceptó la prueba FCM al Pixel 8. Para mostrar avisos fuera de la app, activar notificaciones desde su bandeja y aceptar el permiso de Android.
